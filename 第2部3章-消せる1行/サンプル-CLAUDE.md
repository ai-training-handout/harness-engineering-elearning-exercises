# CLAUDE.md — ShiftBoard

飲食店・小売店向けのシフト管理 Web アプリ。店長がシフトを組み、スタッフがスマホで希望と確定シフトを見る。
開発は5人。本番は約300店舗が利用中。

## スタックと構成

- Next.js 15（App Router）＋ TypeScript
- Prisma ＋ PostgreSQL 16
- 認証は Auth.js（店長・スタッフ・本部の3ロール）
- `src/app/` 画面とルート、`src/server/` 業務ロジック、`prisma/` スキーマとマイグレーション、`tests/` Vitest と Playwright

## コマンド

- 開発サーバー: `pnpm dev`
- 単体テスト: `pnpm test`（特定ファイルだけなら `pnpm test src/server/shift`）
- E2E: `pnpm e2e`（先に `pnpm db:seed` でテスト用店舗を投入する）
- 型検査と lint: `pnpm check`
- マイグレーション作成: `pnpm prisma migrate dev --name <内容>`

## 作業の進め方

1. まず、依頼に関係しそうなファイルをすべて開いて、上から順に読む。
2. 次に、変更するファイルの一覧と変更内容を箇条書きで書き出す。
3. その一覧に沿って、1ファイルずつ変更する。
4. 1ファイル変更するたびに `pnpm check` を実行する。
5. 最後に、変更したファイルをもう一度すべて読み直し、書き漏れがないか確認する。

## 回答のしかた

- 作業を始める前に、どう考えてその方針にしたかを、ステップごとにすべて書き出すこと。
- 変更の説明は日本語で書く。コード中のコメントとコミットメッセージは英語で書く。
- 変更は小さく保つ。1つの PR で直すのは1つの問題だけ。

## 業務ルール（コードを読んでも分からないこと）

- シフトの日付は**店舗のタイムゾーン**で決める。サーバーの時刻（UTC）で日付を切らない。
- 日付をまたぐシフト（22:00〜翌5:00 など）は**開始した日**のシフトとして数える。給与集計がこの前提で組まれている。
- 6時間を超えるシフトには45分、8時間を超えるシフトには60分の休憩を入れる（労働基準法第34条）。休憩が足りないシフトは保存できないようにする。
- 「確定」になったシフトは店長しか変更できない。スタッフの画面から変更できる経路を作らない。
- 本部ロールは全店舗を閲覧できるが、シフトの作成・変更はできない。

## コーディング規約

- 業務ロジックは `src/server/` に置き、画面のコンポーネントから Prisma を直接呼ばない。
- 日時は `src/server/time.ts` の関数だけで扱う。`new Date()` を業務ロジックに直接書かない。
- ファイルを編集する前に、必ずそのファイルの内容を全部読んでから編集すること。
- 長いファイルは途中を読み飛ばしやすいので、300行ずつに分けて読むこと。
- 新しい関数を書く前に、必ず似た関数がないか `src/` 全体を検索してから書くこと。

## 禁止事項

- `any` 型を使ってはならない。
- `console.log` を残したままにしてはならない。
- 未使用の import を残してはならない。
- 1行が120文字を超えてはならない。
- テストを削除してはならない。
- テストを `skip` にしてはならない。
- 依存パッケージを勝手に追加してはならない。
- `.env` と `.env.local` を読んではならない。
- `main` ブランチに直接 push してはならない。
- 関数を50行より長くしてはならない。
- ネストを4段より深くしてはならない。
- マジックナンバーを書いてはならない。
- 変数名をローマ字にしてはならない。
- 既存の API のレスポンス形式を変えてはならない。
- 質問せずに大きな設計変更をしてはならない。
- 推測で答えてはならない。

## Do NOT（過去の事故から）

- Do NOT: `prisma migrate reset` を実行しない。検証環境は開発者全員で共有しており、2026-03 にこれで全店舗のテストデータが消えた。スキーマを戻したいときは、戻すマイグレーションを新しく足す。
- Do NOT: `prisma/migrations/` の既存ファイルを書き換えない。適用済みの本番と履歴がずれ、2026-05 のリリースで本番のマイグレーションが止まった。
- Do NOT: シフトの時刻を `toLocaleString()` で文字列にしてから保存しない。2026-06 に深夜シフトが1日ずれて保存され、給与が二重に集計された。

## 完了の条件

- `pnpm check` と `pnpm test` が通っている。
- シフトの保存・確定・休憩に触れた変更は、`tests/shift/` にテストを足している。
- 画面を変えた変更は、`pnpm e2e` のシフト作成シナリオが通っている。
