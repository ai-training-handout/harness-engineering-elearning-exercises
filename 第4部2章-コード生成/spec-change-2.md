# 仕様変更 2：優先度に `urgent` を追加し、既定を `low` にする

> **`spec.md` の全機能が green になったあとに投入する2本目の仕様**。
> ねらい：既存テストが変更を検知して落ちること＝**回帰**を体験させる。

## 変更内容

`Task.priority` の取りうる値に **`urgent`** を追加し、**既定値を `mid` から `low` に変更する**。

- 新しい enum：`low` / `mid` / `high` / **`urgent`**
- **既定値は `low`**（`priority` を指定せずに作成したタスクは `low` になる。これまでは `mid`）
- 優先度の意味順は **`urgent` > `high` > `mid` > `low`**
- enum 外（`urgent` 以外の未知の値）は従来どおり 422
- UI の優先度セレクトにも `urgent` を追加し、新規作成フォームの初期選択を `low` にする

## テスト要件

- `priority=urgent` でタスクを作成できること（201）。
- `priority` を省略して作成したタスクの `priority` が `low` であること（201）。
- `priority=unknown` は従来どおり 422 であること。
- 既存の既定値テスト・バリデーションテスト・UI テストが、この変更を反映した形に更新されていること。

## 進め方（厳守・順序を変えない）

1. **実装だけを変更する。テストファイルには触らない。**
2. `uv run pytest -q` を回し、**落ちた既存テストを記録する**。

4. 新しい仕様のテストを追加する。

実装とテストを同時に直すと、**既存テストが変更を検知した瞬間が見えない**。回帰が守ってくれたことを確認するために、この順序で進めること。
