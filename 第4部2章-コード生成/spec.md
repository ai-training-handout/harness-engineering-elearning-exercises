# 仕様書：チームタスク管理 Web アプリ「TeamTasks」

> この仕様書が**唯一の正**である。ここに書かれていない機能は実装しないこと。
> 実装は空の状態から行う（既存のアプリコードはない）。

## 1. 技術スタック

Python 3.11+ / FastAPI / SQLite（標準ライブラリ `sqlite3`）/ Jinja2 + HTMX / pytest / Playwright（E2E）

外部の ORM・マイグレーションツール・フロントエンドビルドツールは使わない。

## 2. データモデル

### User

| フィールド | 型 | 制約 |
|---|---|---|
| `id` | int | 自動採番 |
| `name` | str | 一意。シードで固定（`admin1` / `member1` / `member2`） |
| `role` | str | `admin` / `member`（`admin1` が admin、他は member） |

認証はセッション方式の簡易ログイン。**シードユーザーのみ・ユーザー登録機能なし・パスワードなし**（`name` の入力のみでログイン）。シードはアプリ起動時に投入し、既に存在する場合は重複投入しない。

**シードの投入順は `admin1` → `member1` → `member2`** とする（`id` はこの順に 1・2・3 になる）。

DB ファイルのパスは環境変数 `TEAMTASKS_DB` で差し替えられるようにする（未設定時は `teamtasks.db`）。テストはこの環境変数で一時 DB を使う。

### Task

| フィールド | 型 | 必須 | 制約 |
|---|---|:--:|---|
| `id` | int | 自動 | 採番 |
| `title` | str | ✓ | 1〜100文字。空文字・101文字以上は 422 |
| `description` | str | – | 最大2000文字。既定 `""` |
| `status` | str | – | `todo` / `doing` / `done`（既定 `todo`）。enum 外は 422 |
| `priority` | str | – | `low` / `mid` / `high`（既定 `mid`）。enum 外は 422 |
| `due_date` | str \| null | – | `YYYY-MM-DD`。既定 `null`。形式不正・**存在しない日付（例 `2026-02-30`）は 422** |
| `tags` | list[str] | – | 既定 `[]`。**最大5個・各1〜20文字**。超過は 422。重複は取り除いて保存 |
| `assignee_id` | int \| null | – | 既定 `null`。**存在しない User を指定した場合は 422** |
| `created_by` | int | 自動 | 作成したログインユーザー。クライアントからは指定不可（指定されても無視） |
| `created_at` / `updated_at` | str | 自動 | ISO8601（UTC、`Z` 終端）。`updated_at` は更新のたびに必ず変わる |

## 3. 権限ルール

| 操作 | admin | member |
|---|---|---|
| 閲覧（一覧・詳細） | 全タスク | 自分が `created_by` **または** `assignee_id` のタスクのみ |
| 更新（PATCH） | 全タスク | 閲覧できるタスク（作成者 or 担当者） |
| 削除（DELETE） | 全タスク | **作成者のみ**（担当者では削除できない） |

**エラーの出し分け（重要）**：

- **閲覧権限すらないタスク**への操作 → **404**（存在を秘匿する）
- **閲覧はできるが操作権限がない**タスクへの操作（member が「担当者だが作成者でない」タスクを DELETE） → **403**
- 存在しない `id` → **404**
- 未ログイン → **HTML ページは 302 で `/login` へリダイレクト／JSON API は 401**。**未ログインの判定は権限・存在判定より優先する**（未ログインで存在しない id を叩いても 401）

## 4. API 契約

### 4.1 共通

- HTML のベースパスは `/`、JSON API は `/api`。
- JSON のキーは **snake_case**。
- エラーレスポンスは `{"detail": "<説明文字列>"}`（FastAPI 既定の形）。バリデーションエラー（422）は FastAPI 既定の詳細形式でよい。
- 認証はセッション Cookie。

### 4.2 エンドポイント

| メソッド | パス | 種別 | 成功 | 主なエラー |
|---|---|---|---|---|
| `GET` | `/login` | HTML | 200（ログインフォーム） | – |
| `POST` | `/login` | HTML | 302 → `/tasks` | 未知の `name` は 200 でエラー文言を再表示 |
| `POST` | `/logout` | HTML | 302 → `/login` | – |
| `GET` | `/tasks` | HTML | 200（一覧） | 未ログイン 302 → `/login` |
| `GET` | `/tasks/{id}` | HTML | 200（詳細） | 未ログイン 302／権限外・不存在 404 |
| `GET` | `/api/tasks` | JSON | 200（§4.3 の一覧形式） | 未ログイン 401 |
| `POST` | `/api/tasks` | JSON | **201**（作成された Task） | 401／422 |
| `GET` | `/api/tasks/{id}` | JSON | 200（Task） | 401／404 |
| `PATCH` | `/api/tasks/{id}` | JSON | 200（更新後の Task） | 401／404／403／422 |
| `DELETE` | `/api/tasks/{id}` | JSON | **204**（本文なし） | 401／404／403 |

- `PATCH` は**部分更新**。送られたフィールドのみ更新し、送られなかったフィールドは変更しない。`tags` は送られた場合**全置換**（部分追加ではない）。
- `POST /api/tasks` で `created_by`・`id`・`created_at`・`updated_at` が送られても無視する。

### 4.3 レスポンス形状

Task オブジェクト：

```json
{
  "id": 1,
  "title": "レビュー依頼を出す",
  "description": "",
  "status": "todo",
  "priority": "mid",
  "due_date": "2026-08-10",
  "tags": ["review", "urgent"],
  "assignee_id": 2,
  "created_by": 1,
  "created_at": "2026-08-01T09:00:00Z",
  "updated_at": "2026-08-01T09:00:00Z"
}
```

一覧（`GET /api/tasks`）：

```json
{ "items": [ ], "total": 12 }
```

- 並び順は **`created_at` の降順**（同値の場合は `id` の降順）。
- `total` は**権限範囲内の件数**（admin と member で異なる）。
- ページネーションは持たない。

## 5. UI 要件

| 画面 | 要件 |
|---|---|
| `/login` | `name` の入力のみ。未知の名前はエラー文言を表示 |
| `/tasks` | 権限範囲内のタスクを `created_at` 降順で一覧表示（タイトル・status・priority・期限・担当者・タグ）。新規作成フォーム。0件時は「タスクがありません」を表示。ログイン中のユーザー名とログアウトを表示 |
| `/tasks/{id}` | 詳細表示と編集フォーム。権限に応じて削除ボタンの表示を切り替える |
| 共通 | **HTMX による部分更新**：作成・更新・削除の後は該当領域のみ差し替え、ページ全体をリロードしない |

## 6. テスト要件

### 6.1 pytest（必ず実装すること）

1. **CRUD 正常系**：作成（201・既定値が入る）／取得／部分更新（`updated_at` が変わる）／削除（204・以後 404）。
2. **バリデーション（422）**：`title` 空・101文字／`status`・`priority` の enum 外／`due_date` の形式不正と**存在しない日付**／`tags` 6個・21文字／存在しない `assignee_id`。
3. **権限**：member が無関係タスクへアクセス → **404**／member が「担当者だが作成者でない」タスクを DELETE → **403**／同タスクの PATCH は **200**／admin は全操作可。
4. **認証**：未ログインで API → **401**（存在しない `id` を指定しても 401 が優先）／未ログインで HTML → **302 で `/login`**。
5. **一覧**：`created_at` 降順であること／`total` が権限範囲の件数であること（member と admin で異なる）。
6. `tags` の重複が取り除かれること・**5個ちょうどは通ること**（境界）。

### 6.2 E2E（Playwright・1シナリオ）

member1 でログイン → タスク作成（HTMX で一覧に追加される）→ 詳細で status を `doing` に更新 → 一覧に反映されることを確認 → ログアウト。

- E2E の1シナリオが通過。
