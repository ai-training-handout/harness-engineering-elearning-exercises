# /implement — 仕様書から実装を完了させる

引数：仕様書のパス（例 `spec.md`、`spec-change-2.md`）。省略時は `spec.md`。

オプション：

| オプション | 効果 | 用途 |
|---|---|---|
| （なし） | Verify は `pytest → Playwright E2E` の両方を実行 | 既定 |
| `--no-e2e` | **E2E を実行せず pytest だけで Verify する** | コスト比較の計測用（Step 10）。同じ仕様で2回走らせ、検証をどこまで自動化するかとコストのトレードオフを体感する |

`--no-e2e` で走らせた場合は、**E2E を実行していないことを完了報告に明記する**（未検証のまま完了扱いにしない）。

## 手順

### 1. Plan

`planner` サブエージェントを起動し、仕様書から `plan.md` を作らせる。`plan.md` には必ず以下を含める：

- 作成・変更するファイルの一覧（役割つき）
- 主要な関数・クラスのシグネチャ
- **実装するテスト項目の一覧**（仕様のどの条項に対応するかを明記）
- 実装順序（依存関係の順）

**計画が仕様のどこかを取りこぼしていないか**を、仕様書の節番号と突き合わせて自己確認してから次へ進む。

### 2. Implement

`implementer` サブエージェントに `plan.md` を渡して実装させる。

### 5. Finalize

green になったら：

1. ブランチを切る（`feature/<仕様名>`。`--no-e2e` のときは `feature/<仕様名>-no-e2e` にして、E2E ありの実行と混ぜない）。
2. 変更をコミットする。
3. `PR.md` に PR 本文を書く：変更概要/実装した仕様条項/テスト結果（件数と実行コマンド）/レビュー観点で見てほしい箇所。
4. `reviewer` サブエージェントに差分をレビューさせ、指摘があれば解消してから完了とする。

## 禁止事項

- **落ちたテストを削除・skip・期待値の書き換えで通さない**。実装を直すこと。テストの期待値を変更してよいのは、**仕様変更によって期待値そのものが変わった場合だけ**であり、その場合は PR 本文に理由を明記する。
- 仕様書にない機能を追加しない。
- `_instructor/` を読まない。

## 完了報告に含めるもの

- 実装した仕様条項の一覧
- pytest の結果（件数）/E2E の結果
- Verify を何回回したか
- **仕様変更の投入時は、手順2で落ちた既存テストの一覧と、その仕分け結果（期待値更新/実装修正）**
- 打ち切った場合は残課題
