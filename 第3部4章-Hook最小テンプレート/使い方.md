# 第3部4章 演習 #133「整形と危険操作 block を実装する」— 最小テンプレート

演習①（#132）で選んだ「毎回整形したい編集」と「絶対に止めたい危険操作」を、2つのフックとして自分のプロジェクトに入れるための土台。書き換えるのは各スクリプトの「▼ ここを自分のプロジェクトに合わせる」の部分だけでよい。

| ファイル | 役割 | 置き場所 |
|---|---|---|
| `hooks-settings-snippet.json` | 2つのフックの登録（#124 の書式。`matcher` の下に `hooks` 配列を入れ子にする） | 中身の `hooks` を、自分のプロジェクトの `.claude/settings.json` に貼る |
| `.claude/hooks/format.sh` | PostToolUse：Edit・Write のあと、拡張子ごとの formatter をかける | 自分のプロジェクトの `.claude/hooks/` |
| `.claude/hooks/block_dangerous.sh` | PreToolUse：Bash の実行前に、コマンドの文字列を見て止める（#127 の骨格） | 同上 |

## 入れ方

```sh
cd <自分のプロジェクト>
mkdir -p .claude/hooks
cp <このフォルダ>/.claude/hooks/*.sh .claude/hooks/
chmod +x .claude/hooks/*.sh
# hooks-settings-snippet.json の "hooks" を .claude/settings.json に貼る（既に hooks があれば、イベント名ごとに配列へ足す）
```

スクリプトは `python3` で標準入力の JSON を読む（`jq` が無くても動く）。

## 動作確認（#133 の3つ）

Claude Code を起動し直してから確かめる（設定は起動時に読まれる）。先に、Claude Code を通さずスクリプトだけを叩いて確かめると切り分けが楽。

```sh
# 整形：編集されたファイルのパスを渡す → exit 0 で、ファイルが整形される
echo '{"tool_input":{"file_path":"src/example.py"}}' | .claude/hooks/format.sh; echo "exit=$?"

# 危険操作：止めたい文字列を含むコマンド → exit 2 と理由の文言
echo '{"tool_input":{"command":"git push --force origin main"}}' | .claude/hooks/block_dangerous.sh; echo "exit=$?"

# 通常時：関係ないコマンド → exit 0 で何も出ない
echo '{"tool_input":{"command":"git status"}}' | .claude/hooks/block_dangerous.sh; echo "exit=$?"
```

- **危険操作の確認は、本物の本番環境では試さない。** Claude Code で試すときも「`echo "git push --force"` を実行して」のように、検知したい文字列を含むだけの無害なコマンドで確かめる。
- **何でも止めるフックは、仕事まで止める。** ふだんのコマンド（`git status`・テストの実行）が素通りすることも必ず確かめる。
- 発火しないときは、まず `settings.json` の入れ子の形（`hooks` が2回出る）と、`matcher` に書いたツール名（`Edit|Write`・`Bash`）を見直す。
- 文字列で見るので、書き方を変えたコマンド（フルパス・`bash -c` 経由など）はすり抜ける。被害の範囲は Permissions の deny（第3部5章）やサンドボックス（第6部4章）と重ねて囲う。
