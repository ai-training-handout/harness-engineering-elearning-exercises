# 仕様抜粋：タスク検索・絞り込み機能の追加

> この PR がレビュー対象とする仕様。**レビューはこの抜粋との照合で行う**（アプリ仕様の全文は渡さない＝コスト制御）。

## 機能概要

タスク一覧（HTML：`GET /tasks`、JSON：`GET /api/tasks`）に検索・絞り込み・ソート・ページネーションを追加する。両エンドポイントは同一のクエリパラメータ・同一の絞り込み結果を返すこと。

## クエリパラメータ

| パラメータ | 内容 | 制約・エラー |
|---|---|---|
| `q` | `title`・`description` の部分一致（大文字小文字を区別しない） | – |
| `status` | 複数指定可（例 `status=todo&status=doing`） | enum 外は 422 |
| `priority` | 単一指定 | enum 外は 422 |
| `tag` | 単一指定。完全一致 | – |
| `assignee_id` | 単一指定 | 数値でなければ 422 |
| `due_from` / `due_to` | `YYYY-MM-DD`。範囲は両端を含む | 形式不正は 422。**`due_from` > `due_to` は 422** |
| `overdue` | `true` のとき「`due_date` が**今日より前（当日は含まない）** かつ `status != done`」のみ | `true` 以外の値は 422 |
| `sort` | `due_date` / `priority` / `created_at`（既定 `created_at`） | 対象外キーは 422 |
| `order` | `asc` / `desc`（既定 `desc`） | enum 外は 422 |
| `page` | 1以上（既定 1） | 0以下・非数値は 422 |
| `per_page` | 既定 20・最大 100 | 0以下・101以上は 422 |

## 正しさの定義

1. **複数条件は AND で合成**する。
2. **権限との合成**：検索・絞り込みは**閲覧権限のある範囲に対して**行う。member の検索結果・総件数は自分の関与タスクのみ（admin と結果が異なる）。
3. **`priority` のソートは意味順**（`urgent` > `high` > `mid` > `low`）。文字列辞書順にしない。
4. `due_date` 未設定のタスクは、`due_date` ソート時は末尾（asc/desc とも）、`overdue=true`・`due_from`/`due_to` 指定時は対象外。
5. ページネーション応答には**総件数・現在ページ・総ページ数**を含める。一覧レスポンスは `{"items": [...], "total": n, "page": n, "per_page": n, "total_pages": n}`。範囲外ページは空リスト（200）。
6. **絞り込みは SQL レベルで行う**こと（全件を Python に読み込んでからのフィルタは不可）。
7. UI：一覧上部に検索フォーム（HTMX で結果領域のみ差し替え）、ヒット総件数の表示、0件時のメッセージ、ページャ（検索条件はページ遷移後も保持）。

## テスト要件

1. `q` 部分一致（title／description、大文字小文字無視）。
2. `status` 複数指定・`priority`・`tag`・`assignee_id` の各絞り込み。
3. `due_from`/`due_to` の境界（両端を含む）。`due_from` > `due_to` → 422。
4. `overdue=true`：前日期限は含む・**当日期限は含まない**・`done` は含まない。
5. **`priority` ソートが意味順**であること。
6. **member で検索すると自分の関与タスクのみヒットする**こと（admin との件数差を検証）。
7. `page`/`per_page` の境界（0・101 → 422、範囲外ページ → 空リスト 200）。
8. 複合条件（`q` + `status`）が AND になること。
