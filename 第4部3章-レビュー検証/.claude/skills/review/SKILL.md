# /review — PR の多観点レビューとマージ判定

引数：`sample-pr`（固定サンプル PR）または PR 番号（`#123`）。

オプション：

| オプション | 効果 | 用途 |
|---|---|---|
| （なし） | 4観点を**並列**実行。diff と仕様抜粋のみを渡す | 既定。**最も速い**（実測で一貫）。トークンは環境依存 |
| `--sequential` | 4観点を**逐次**実行 | 並列との比較計測。**「直列にすれば安くなる」という直感を自分の環境で検証する**ためのもの（安くなる保証はなく、測る環境で大小が入れ替わる） |
| `--budget` | Blocker 早期打ち切りを有効化（下記） | **Block 確定を早く知る**ためのもの。代償は perf・readability の指摘が出ず一巡で終わらないこと |

## 手順

### 1. Intake

対象を特定し、[入力の取得方針.md](../../../入力の取得方針.md) に従って**必要な範囲だけ**取得する。

- `sample-pr`：`sample-pr/` の diff・`PR.md`・`spec-excerpt.md`。
- 実 PR：GitHub MCP で PR 本文と変更ファイルの patch を取得する。ファイル全文は原則取らない。

対象の妥当性は UserPromptSubmit Hook が実行前に検証済み。**ここで対象を勝手に変更しない**。

### 2. 並列レビュー

4つのレビュアーサブエージェントを**並列に**起動する（`--sequential` の場合は順に1つずつ）。

- `correctness-reviewer`
- `security-reviewer`
- `performance-reviewer`
- `readability-reviewer`

各レビュアーには**同じ入力（diff と仕様抜粋）**を渡す。**観点をまたいだ情報共有はしない**——独立した目で見ることが、観点の混線と自己採点バイアスの排除につながる。

**サブエージェントへの指示文は実行ごとに書き起こさない。** オーケストレーターが渡すのは「レビュー対象の入力の場所」だけとし、**評価基準・重大度の付け方・格上げ禁止の歯止め（「格上げしない」「指摘をひねり出さない」「指摘がなければ『指摘なし』と書く」）は、各レビュアーの定義（`.claude/agents/*-reviewer.md`）と `CLAUDE.md` に固定する**（**Step 1・Step 3 であなたが書く**。配布時点ではまだ無い）。オーケストレーターがこの歯止めを毎回言い換えて渡すと、入る回と入らない回が生まれ、Nit 罠の格付けが実行ごとにぶれる（2026-08 実測で確認）。**歯止めはハーネス側（固定の system prompt）に置き、実行時の裁量に委ねないこと。**

### 3. 集約と判定

`aggregator` サブエージェントに4観点の所見を渡し、集約・判定させる。判定ルールは `CLAUDE.md` のとおり機械的に適用する。

- Blocker ≥1 → **Block**
- Major のみ → **Request Changes**
- Minor 以下 → **Approve**

### 4. 報告

`.claude/output-styles/review-report.md` の様式で、判定・指摘一覧・観点別サマリ・GitHub コメント用 Markdown を出力する。

## Blocker 早期打ち切り（`--budget` で有効化）

correctness と security を先に走らせ、**Blocker が出たら残り2観点（performance・readability）を実行せずに判定へ進む**（Block は確定するため）。

打ち切った場合は、**打ち切ったことと未実行の観点を報告に明記する**（黙って省略しない）。

> **実測でわかっていること（正直に扱う）**：2観点を実行しないぶんトークンが必ず減るとは限らない。打ち切りの判断そのもの（先に2観点を走らせ、結果を見て残りを止める）にオーケストレーションのコストがかかり、**環境によってはトークンが減らない/むしろ増える**（旧環境では14%増を観測）。トークン削減の手段として当てにしないこと。
> **このオプションで得られるのは節約ではなく「Block 確定を早く知ること」**であり、代償は performance と readability の指摘が得られず**修正が一巡で終わらない**こと（この代償は環境をまたいで一貫する）。

## このハーネスがやらないこと

- **コードを書き換えない**。指摘するだけ（Permissions でも編集・push を deny している）。
- 反復ループを持たない。一方向のパイプラインである（レビューの独立性を優先するため）。
